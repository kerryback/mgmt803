Managing Claude

Esc stop what it is doing, and keep the conversation
Esc twice jump back to an earlier message and take a different path
Ctrl-C twice kill Claude Code outright
claude start it again, in a new conversation
Up arrow your previous prompts
Shift-Tab cycle the permission mode

Esc stops a wrong turn without throwing away the context you built. Two Ctrl-Cs are for when the process itself is stuck. In lab803, press Enter after that to reconnect.

Resume and continue

Every conversation is written to disk in your container as you go.

What you get
claude a new, empty conversation
claude --continue the most recent one, where you left it
claude --resume a list of your past conversations, to pick from

So the answer to a stuck terminal is always the same: two Ctrl-Cs, then claude --continue.

Slash commands

Typed into Claude, not into the shell.

/clear wipe the conversation and start fresh without leaving
/resume switch to another conversation from inside this one
/rename name this conversation so you recognize it in that list
/help everything available

A conversation that has wandered sends all of that back to the model on every turn — you pay for it, and it crowds out the question you asked.

A few more worth knowing

/context what is filling the context window right now
/cost what this session has cost so far
/model change models mid-conversation
/permissions what is allowed without asking
/init write a starting CLAUDE.md for this folder
/mcp · /plugin connectors and plugins

Three prefixes work without a slash: ! runs a shell command directly, @ points at a file, and # adds a line to memory.

6 · Prompting tips

Plan

Prompt

Think about the best way to do this, formulate a plan, and tell me what your plan is.

Afterwards

Prompt

Explain what you did step by step. Did you make any decisions that we have not discussed? Write this as an HTML doc.


HTML is easy for AI to write and easy to read. Double-click an HTML file in File Explorer (Finder on Mac) and it will open in your browser.

Numbers need code

If a number appears in prose and no code produced it, it was predicted.

Prompt

Compute this in Python and show me the code and the output. Do not report a number you did not compute.

The same rule applies to counts, percentages, dates, and anything summed across rows.

Verify claims

Ask what would falsify it

“What would have to be true for this to be wrong, and how would I check?”

Make it show its source

The file, the row count, the line of code.

Generator–critic

  1. Get the first answer.
  2. Start a fresh conversation and give it the answer without the reasoning that produced it.
  3. Ask it to find what is wrong with it.
  4. Take the objections back to the first conversation.

The second conversation has no stake in the first answer.

Good enough prompting

Most ‘prompt engineering’ techniques from a few years ago are now either useless or actually counterproductive. Don’t tell it “you are an expert data scientist” or “think step by step.”

Tell it what you want, not what to do

I want … How can we do it?

If something doesn’t work

Try again.

Treat AI as an infinitely patient colleague with a poor memory.

AI is a prediction machine, not a rational person

Suppose an AI agent has told you in the path that Method A beats Method B for some task. You ask it to do the task.

Do not assume it will use what it knows. If “A beats B” is not in the context window, and B appeared more often in its training data, it will probably use B.

This is the value of “plan before you act.” Planning surfaces “A beats B,” leading Claude to select A for the task.

Try it: planning

Three rigs, twenty wells, minimize lost production: workover.md. At lab803 it is in data/.

  1. Upload workover.md and ask: Find the best routes for the rigs.
  2. Start a new conversation (/clear in the Claude tab). Upload the file again and ask: Plan how to do this and share your plan. Read the plan, then ask it to proceed.

Did it use the same method both times?

Try it: explain and critique

  1. Ask: Write an HTML doc explaining what you did, step by step.
  2. Start a new conversation. Tell it to read the HTML doc and ask: Read this and critique the method.

7 · Permissions

What Claude asks before it acts

Mode What it does
Manual asks before the first use of each tool
Plan reads and explores, edits nothing
Accept edits file edits go through without asking
Auto approves on its own, with a check on each action
Don’t ask refuses anything it would otherwise ask about
Bypass no prompts at all

Enforced by the program around the model, not by the model. A line in CLAUDE.md shapes what Claude tries to do; it does not change what is allowed.

Permissions in Claude Desktop

The desktop app runs Claude Code, so the modes are the same and carry the same names.

What it can reach the folders you connect to the conversation, and nothing else
What it asks about the first use of each tool, in Manual mode
What “don’t ask again” does writes a rule that outlives the conversation

Granting a folder is the decision that matters. The mode decides how often you are asked; the folder decides what can be reached at all.

Permissions in your container

Everything is allowed already, in ~/.claude/settings.json:

"permissions": {
  "allow": ["Bash(*)", "Read(*)", "Write(*)", "Edit(*)",
            "Glob(*)", "Grep(*)", "WebFetch(*)", "WebSearch(*)"],
  "deny": []
}

So nothing prompts you all week. That is a decision about this container — it holds your course files and is reachable only by you — not about how to run an agent on your own machine.
