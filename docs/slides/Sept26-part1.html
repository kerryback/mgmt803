10 · Creating HTML with AI

Four things to build, in order of how much the page does.

Why HTML

It is the format AI writes best, and the only one that opens on every machine with nothing installed.

A Word file needs Word, or something that reads it
A notebook needs Python and Jupyter
A dashboard needs a server running somewhere
An HTML file double-click it

One file. Email it, put it in a shared drive, or serve it on the web unchanged.

Four things to build

  1. A report — headings, tables, a figure, sources.
  2. The same report with charts you can hover over and zoom.
  3. A page that computes something when the reader changes an input.
  4. A slide deck with those elements on the slides.

Each one is the previous one plus something the reader can do.

A report

What we are building

A report on which AI models run on a laptop, and what each size is good for.

You have used hosted models all week — in the browser, in your container, through a connector. This asks the opposite question: what runs on hardware you own, with no account and no network.

Pick your own subject if you have one. The shape of the exercise is the same.

What the report has to contain

Facts it must get right

  • Model sizes, and the memory each needs
  • What quantization does to both
  • Which tasks each size handles

Form it must take

  • Headings and a table of contents
  • At least one table and one figure
  • A source for every number

Asking for it

Prompt

Research which AI models can run locally on a laptop and what each size is useful for. Write it as a single self-contained HTML file. Include a table of model sizes against memory required, and cite a source for every number. Do not state a figure you did not find.

Reading it in the lab

Serve the folder and open the View tab:

cd <folder> && python3 -m http.server 8000

Or download the file from the file browser and double-click it. Kill a server before starting another: kill $(lsof -t -i:8000).

Build the report

Exercise

  1. Ask for the report. Give it the subject and the two lists from two slides back.
  2. Open it. Check that every number has a source and that you can reach the source.
  3. Find one number it did not source, and ask where it came from.
  4. Ask it to fix what you found, and open it again.

A report that looks finished and cites nothing is the failure mode. Check the citations before the formatting.

Charts you can touch

What interactive buys you

A picture of a chart

The reader sees what you chose to show them, at the size you chose.

A Plotly chart

Hover for the value, zoom into a range, click a legend entry to drop a series.

Same file, still one file. The chart is JavaScript that ships inside the page.

Two ways to include it

What it does Cost
include_plotlyjs="cdn" a script tag pointing at Plotly’s server small file, needs the network to open
include_plotlyjs=True the whole library inside the file opens anywhere, several MB

Python: fig.write_html("chart.html", include_plotlyjs="cdn"). Choose True for anything you email.

Add the charts

Exercise

  1. Take the report you just built and ask for the table as a chart as well.
  2. Ask for it self-contained, then check the file size.
  3. Open it and try all three: hover, zoom, click the legend.
  4. Ask for a second chart that answers a question the table does not.

Pages that compute

A single-page app

One HTML file, holding its own inputs and the code that responds to them. No server, no install, no account.

The page

Inputs, a button, somewhere to put the answer.

The code

JavaScript, or Python through Pyodide, running in the reader’s browser.

The reach

Anyone you send it to can use it. Nothing of theirs leaves the page.

Two kinds of app in your container

Runs where Start it with
Single-page HTML the reader’s browser python3 -m http.server 8000
FastAPI your container uvicorn <module>:app --host 0.0.0.0 --port 8000

Only the first is a file you can send someone. The second needs your container to stay running.

Build an app

Exercise

  1. Pick a calculation you have done twice this year with a spreadsheet.
  2. Ask for it as a single self-contained HTML file with inputs and a result.
  3. Open it, put in a case you know the answer to, and check it.
  4. Ask for one input you did not think to include, and say why it matters.

A wrong answer that appears instantly is worse than a spreadsheet. Test it against a case you already know.

Slides that do something

A deck is also a web page

These slides are reveal.js — HTML, in a browser. Anything that goes on a page can go on a slide.

What you gain

A chart the audience can interrogate during the question. A figure that answers what they actually asked.

What you give up

It is not PowerPoint. Nobody can edit it without the source, and it will not open in the room’s podium software.

Build a deck

Exercise

  1. Ask for a five-slide reveal.js deck on the report’s findings.
  2. Put one of your Plotly charts on a slide and check it still works there.
  3. Present it from the browser, full screen, and try the chart in front of someone.

11 · Git and GitHub

Keeping every version of the work, and putting the four files on the web.

What a commit is

A version control system tracks every change you make. A commit is a snapshot you can return to.

Install

Claude Code installs Git if it is not already there.

Commits

Ask it to commit, and the change is saved with a description of what it was.

History

Ask when something changed, what changed it, or what the file looked like three versions ago.

GitHub

GitHub hosts Git repositories. The project lives in the cloud, backed up and shareable.

Pushing

With a free account, Claude Code pushes your repository to GitHub and pushes later commits when you ask. It uses the GitHub CLI.

Collaboration

Others can clone it, propose changes, and open issues. Working alone, it is backup and deployment.

Claude Code installs the CLI and handles the sign-in. Tell it: push this project to a new GitHub repo.

GitHub Pages

Any repository becomes a website. No server, no configuration, no cost.

  1. Name the landing page index.html.
  2. Push the repository to GitHub.
  3. Settings → Pages, and set the source to the main branch, either its root or a docs/ folder.
  4. The site is live at yourusername.github.io/repo-name/.

A custom domain costs about $15 a year and replaces the github.io address.

You have been reading one all week

Repository github.com/kerryback/mgmt803
Source the main branch, docs/ folder
Address mgmt803.kerryback.com

The slides, the syllabus and the files are a folder of HTML that Quarto writes and Pages serves. Nothing else is running.

What Pages will and will not host

From this morning On Pages
The report works
The page of Plotly charts works
The single-page app works
The reveal.js deck works
A FastAPI app no — it needs a server running

Before you push

A free Pages site is public. Anyone who finds the address can read every file in the folder, and anyone can read the repository.

Keep out

API keys, passwords, anything under a data agreement, and anything with a name in it.

Remember

Deleting a file in a later commit does not remove it. It stays in the history.

Publish this morning’s work

Exercise

  1. Put the four files in one folder and ask Claude Code to make it a Git repository.
  2. Ask what it is about to commit, and read the list before it does.
  3. Have it push to a new GitHub repository and turn on Pages.
  4. Open the address on your phone.
  5. Change one line, commit, push, and watch the site change.

Step 2 is the habit worth keeping. It is the last point at which a key is easy to remove.
