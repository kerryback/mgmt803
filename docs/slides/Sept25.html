17 · Creating agents

A chatbot produces text

It receives text and returns text. That is the entire capability.

  • Everything it “knows” arrived as text in the request
  • Everything it “does” leaves as text in the response
  • No files, no network, no memory between conversations

A chatbot that appears to remember you is being handed the earlier conversation again on every turn.

An agent is a chatbot with tools

  1. You send a request. The harness also sends a list of tools and what each one does.
  2. The model answers with text, or with a request to use a tool.
  3. The harness runs the tool and puts the result back into the conversation.
  4. Repeat until the model answers with text and no tool call.

What the model is sent

Every turn, the harness assembles one block of text:

Fixed each turn

The system prompt. The tool definitions. Any instruction files the harness is coded to include.

Growing each turn

Your messages, the model’s replies, and the full output of every tool that has run so far.

A tool result is text in the conversation, which is why a document the agent read can change what it does next.

How software works

Frontend and backend

Frontend

The browser. HTML, CSS and JavaScript — it draws the page and collects the clicks.

Backend

A program on a server, listening continuously for requests. Yours will be Python.

You open a URL. The browser sends a request. The server sends back HTML, CSS and JavaScript. The browser interprets that and shows you a page.

Right-click any page and choose View Page Source. That is the frontend code, exactly as the backend handed it over.

Two kinds of request

What it carries What the server does
GET a path, and parameters in the URL sends back a page, or data
POST a body — a form, a ticker you typed whatever it was written to do, then replies

Opening a page is a GET. Clicking submit is usually a POST.

Running it on one machine

The frontend and the backend can be the same computer — your container, or your own laptop with Python on it.

localhost

127.0.0.1 is the loopback address. The browser asks the machine it is already running on, and the request never reaches a network.

Ports

One machine runs many programs listening at once. The port number tells the operating system which of them gets the request.

You write the app as a .py file. FastAPI is the usual Python library for one, and uvicorn starts it listening: uvicorn app:app --host 0.0.0.0 --port 8000.

Build something interactive

Exercise

  1. Ask for a small FastAPI app with one page and one input — a unit converter, a loan payment, anything with a number in and a number out.
  2. Run it: uvicorn app:app --host 0.0.0.0 --port 8000, and open the View tab.
  3. Watch the terminal while you use it. Opening the page logs a GET; submitting the form logs a POST.
  4. Change one thing and reload. Kill the old server first: kill $(lsof -t -i:8000).

The API

A fourth interface

Interface Who is at the keyboard What it is for
Chat in a browser you one question
Claude Code you work on a machine
A connector you, inside another tool reaching your data
The API a program the same operation, many times

The first three assume a person is present. The API does not.

An API call in Python

import anthropic

client = anthropic.Anthropic()          # reads ANTHROPIC_API_KEY

resp = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=500,
    system="You classify customer complaints. Answer with one word.",
    messages=[{"role": "user", "content": "The unit arrived cracked."}],
)

print(resp.content[0].text)

The same call through OpenRouter

import os
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
resp = client.chat.completions.create(
    model="nvidia/nemotron-3.5-lightning:free",
    messages=[{"role": "user", "content": "The unit arrived cracked."}],
)
print(resp.choices[0].message.content)

A different library, a different response shape, and the model is a string you can change. Free accounts are capped at fifty requests a day.

Get two keys

Anthropic

platform.claude.com → API keys → Create key. Pay per token, so set a spending limit on it.

OpenRouter

openrouter.ai → Keys → Create key. Sign in with Google or GitHub, no card. One key reaches every provider it carries.

Both are shown once. Copy each into a file called env.txt, one per line, and upload it to your container from the Files tab. Then tell Claude: my keys are in env.txt.

The key

  1. Create a key in the console. It is shown once.
  2. Put it in an environment variable, not in the code.
  3. Never commit it. A key in a public repository is found in minutes.
  4. Set a spending limit on the key before you use it in a loop.

A loop over a large file with a bug in the exit condition spends real money.

What you are charged for

Input tokens and output tokens, priced separately, per million.

Input everything you send — instructions, tool definitions, the whole conversation so far
Output only what comes back

A conversation costs more each turn because the entire history is sent again every time. In an agent loop, every tool result joins that history.

The loop

What an agent is, exactly

A model

Which one, and at what temperature.

A system prompt

What it is for, and what it refuses.

A tool list

Everything it can do. Nothing else is possible.

A permission mode

Which actions stop for approval.

A place to run

A machine, a directory, a network.

A loop

Call, execute, feed the result back, repeat.

Three kinds of tools

Where the code is Example
Built in in the harness read a file, run a command, fetch a page
Yours a function you wrote look up a customer in your system
Someone else’s an MCP server the Northwind database, EIA, FRED

All three arrive at the model the same way: a name, a description, and a parameter schema.

A tool you write

@tool("order_total",
      "Total revenue for one order. Takes an order id.",
      {"order_id": int})
async def order_total(args):
    df = pd.read_excel("northwind_orderdetails.xlsx")
    rows = df[df.OrderID == args["order_id"]]
    total = (rows.UnitPrice * rows.Quantity).sum()
    return {"content": [{"type": "text", "text": f"${total:,.2f}"}]}

The description is the interface. The model never sees the code.

Tools from an agent SDK

Pre-built code for the harness, and a set of tools that come with it. The Claude Agent SDK, the OpenAI Agents SDK, LangChain.

Read        Write       Edit
Glob        Grep        Bash
WebSearch   WebFetch    Task

The built-ins in the Claude Agent SDK. You choose which to include: tools=[] includes none, and naming a few includes only those.

Where they run

Read, Write, Edit, Bash, Grep the agent’s own process — its filesystem, its shell, its network
Internal MCP tools the same process — whatever it can import, it can run
External MCP tools someone else’s server — arguments out over HTTP, only the result back
WebSearch Anthropic’s search backend — titles and URLs, not pages
WebFetch downloads from your machine, then a small model extracts what was asked

So “on your machine” holds for the filesystem and shell tools. The two web tools are not local: the search runs at Anthropic, and the fetched page is sent there to be read.

Agent options

ClaudeAgentOptions
system_prompt a string, or a file on disk when it is long
tools which built-ins to include — tools=[] for none
disallowed_tools takes a tool out of the model’s context entirely
allowed_tools the tools that run without prompting
mcp_servers the servers to connect, plus the one holding your tools
max_turns how many tool-use round trips before the app stops it

allowed_tools is not a whitelist. A tool left off it still runs — it falls through to permission_mode.

Permission modes, in code

permission_mode
default prompts before file edits, shell commands, and network requests
acceptEdits auto-approves edits and common filesystem commands
plan read-only — proposes changes but makes none
dontAsk only allowed_tools run; anything else is denied, not prompted
bypassPermissions everything runs, no checks — sandboxed containers only

Build one

Exercise · three stages

  1. A chatbot with no tools at all. Ask it how many files are in the directory it is running in. Read the answer carefully.
  2. Give it one built-in tool — reading files — and ask again.
  3. Write a tool of your own over data you brought or the order spreadsheets. Give it a system prompt that says what it is for.

In stage 1 the model has no way to see the directory. Keep its answer — you compare it against stage 2.

What stage 1 shows

Asked a question about a filesystem it cannot reach, a model with no tools still answers.

  • It produces a plausible number
  • It produces plausible filenames
  • Nothing in the output is marked as unavailable

The same model with a file-reading tool answers correctly. What changed is the tool list.

Choosing what it can do

A general agent and a narrow agent

A general agent A narrow agent
Tool list everything three tools
Runs as you a service account
Reaches your whole machine one dataset
Right for your own work anything you hand to someone else

An agent whose tool is an agent

  1. An orchestrator receives the question and holds no data of its own.
  2. It calls a research agent that can read the public web and nothing private.
  3. It calls a data agent that can read your database and cannot reach the internet.
  4. It assembles the answer from what both returned.

The two workers never share a context, so neither holds private data and an outbound channel at the same time.

18 · Managing security risks

Believing it, sending it out, and letting it act.

Three risks

Believing it

A wrong number, delivered fluently. Friday morning was this one.

Sending data out

Your material reaching a third party. A contract problem.

Letting it act

An agent doing something on your behalf that you did not ask for. An engineering problem.

Most corporate AI policy addresses the second one only.

Sending data out

What a contract gives you

What it adds Enough for
Opt out of training a setting, revocable, data still retained briefly personal, non-sensitive work
A signed DPA liability, breach notice, audit rights, a subprocessor list client data, regulated data
A DPA plus a BAA the same, covering protected health information anything under HIPAA
An enterprise agreement SLAs, support, SSO, capacity scale and operations

The last row buys operations. The privacy terms are the same as the row above it.

What the regulation actually requires

HIPAA

Satisfactory assurances “must be documented through a written contract” meeting §164.504(e).

A BAA is required, not advisable. 45 CFR 164.502(e).

SEC Reg S-P

Written policies “reasonably designed to require oversight, including through due diligence and monitoring, of service providers.”

17 CFR 248.30.

Run it where the data already is

AWS Google Cloud Azure
Claude Bedrock Vertex AI Foundry
GPT Bedrock Azure AI Foundry
Gemini native

If the data already sits in one of those, the model can run inside the same perimeter. No new vendor, no new trust boundary, and the DPA you already signed still applies.

When the contract is not enough

  1. Send less — a schema and a few synthetic rows rather than the table.
  2. Anonymize — strip the names, the account numbers, the identifiers.
  3. Run a smaller model on your own hardware, so nothing leaves at all.

A DPA is a promise backed by liability. These three are physical facts about where the data went.

Letting it act

Prompt injection

The model cannot tell an instruction from a piece of content. Both arrive as text in the same conversation.

Text placed where the agent will read it — an email, a document, a web page, a spreadsheet cell — is read in the same way as text you typed. An attacker needs no credentials, only a way to get words in front of the model.

OWASP has ranked this first among risks to LLM applications since 2025.

EchoLeak

CVE-2025-32711 · Microsoft 365 Copilot · June 2025

  1. An attacker mails the victim a message containing instructions invisible to a human reader.
  2. The victim asks Copilot to summarize their email. Copilot reads the hidden instructions.
  3. Following them, Copilot places confidential data inside a URL in its response.
  4. The victim’s browser fetches that URL automatically.
  5. The attacker reads the data out of their own server log.

Zero clicks by the victim beyond the summary request.

Three legs

Private data

Something worth taking: client records, financials, an inbox.

Untrusted content

Text an outsider can control: a web page, an email, an uploaded file.

An outbound channel

Any way for text to leave: fetching a URL, sending mail, writing somewhere shared.

All three in one agent is the condition. Remove any one and the attack does not work.

The question to ask about any deployment

The check

Does this agent hold private data, read content an outsider can influence, and have a way to send text out — at the same time?

It is answerable from an architecture diagram, without knowing anything about how the model works.

Blast radius of an Excel add-in

The Claude for Excel add-in from Thursday, checked against the three legs.

Private data

The open workbook. With “work across files” on, also the open deck, the open Word document, and the open Outlook email.

Untrusted content

A downloaded template, a vendor file, a data import, or an email from outside.

An outbound channel

Writing into the open document or email, and any connector you have enabled.

“Work across files” is on by default for Pro and Max plans and off by default for Team and Enterprise. Anthropic’s testing found the add-in could be manipulated into extracting sensitive information, modifying data, or taking destructive actions.

Isolation and governance

Two ways to stop the same thing

Governance

Every call is inspected as it is made and allowed or refused.

Works on the calls you anticipated. Judgment happens at run time, every time.

Isolation

The route does not exist.

Works on calls nobody anticipated. There is nothing to judge at run time.

Real systems use both. The order matters: isolate first, then govern what remains.

Where the call is made from

In Claude Cowork, and in most setups a firm will hand you, the machine the agent’s shell runs on has no route to the internet. The connector works anyway.

At the shell

curl https://api.stlouisfed.org/...

Refused. Everything leaving that machine passes a proxy that allows a short list of addresses, and that is not one of them.

Through the connector

fred_get_observations("UNRATE")

Rows come back. Same machine, same model.

Because your machine never places the call. The client end sits outside it, calls FRED itself, and hands the rows back into the conversation. Your key goes with it and is never on the machine.

What each option allows

Open the network instead

Allow the machine to reach stlouisfed.org and it can send anything to any address there, in any form it likes.

Leave it shut, add a connector

It can call run_sql with a SELECT. That is the entire new capability.

The network stays off and the connector goes on.

The connector reaches out from outside the sandbox holding your credentials, so a sentence in a file it reads can ask for that call.

The split

  1. The agent that reads untrusted content gets no private data and no credentials.
  2. The agent that holds private data has no route to the internet.
  3. An orchestrator calls both as tools and never exposes one to the other’s context.

Neither worker ever holds all three legs. That property is a fact about the network and the tool lists, not a rule either agent has been asked to follow.

Your container, as an example

Filesystem its own — no other student’s files exist inside it
Processes its own — you cannot see anyone else’s
Network its own namespace, and it cannot reach a peer container
The gate your terminal sits behind your own login

Your container is an instance of that pattern.

The Northwind MCP server

A read-only server over the Northwind trading database, at https://northwind-mcp.rice-business.org/mcp.

list_tables every table in the database
describe_table column names and types for one table
query_northwind a read-only SELECT, returned as CSV

query_northwind reads only categories, customers, order_details, orders and products. There is no tool that writes.

Connect it yourself

Add it to Claude Code in one command:

claude mcp add --transport http --scope user \
  northwind https://northwind-mcp.rice-business.org/mcp

claude mcp list shows it connected; /mcp inside Claude lists the three tools. --scope user makes it available from any directory — drop the flag and it lives only in the current project.
